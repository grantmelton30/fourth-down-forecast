# Reliability and UI upgrade — 2026-08-10

This revision turns the repository into a safer research system. It does **not** claim
that the models now beat the market. That conclusion requires a fresh, frozen-data
backtest after the caches are rebuilt. Until every required promotion gate passes, the
application fails closed and will not present probabilities as selections.

## What changed

- Removed the NCAA target-season feedback path from canonical football projections.
  Opener-conditioned diagnostics remain available under explicit
  `model_*_market_adjusted` names and are fit from prior data only.
- Replaced fractional score translation with probability reweighting on the original
  football score lattice. Integer scores, pushes, and key-number atoms are preserved.
- Added free intercepts to NFL residual blends and season/week-clustered covariance.
  Applied slopes are bounded, while raw slopes and clamp decisions remain auditable.
- Added season-block bootstrap inference so repeated games are not treated as independent.
- Added content-addressed cache manifests that include configuration, complete input
  columns, and the relevant source tree. Stale caches are rejected.
- Added a central fail-closed promotion-gate registry and gate artifacts tied to code,
  configuration, data evidence, and cutoff date.
- Isolated NFL and NCAA imports in the combined viewer, avoiding the shared top-level
  `src` package collision.
- Added a root dependency lock and an isolated test runner.
- Refreshed the Streamlit interface as a calm, high-density game-analysis workspace.
  The UI reads the same public model results and calibrated weights; it does not modify
  inference, simulation, caches, or gate decisions.

## Reproducible setup

```bash
uv sync --dev
uv run python run_tests.py
```

The test runner intentionally starts the shared, NFL, and NCAA suites in separate Python
processes. Do not combine both league suites in one `pytest` process: both repositories
use a package named `src`.

## Before evaluating or publishing a slate

1. Rebuild the applicable historical/raw caches from their documented sources.
2. Run each league's `run_backtest.py` in its own repository.
3. Inspect the newly written gate artifact and backtest report.
4. Treat any missing, stale, negative-slope, or failed required gate as a blocker.
5. Only compare the revised model with the market using forward or genuinely held-out
   seasons. Metrics copied from the earlier code are not evidence for this revision.

## The real benefit

The main benefit is trustworthy failure. The old system could look persuasive while
using future-dependent corrections, omitted-intercept regressions, optimistic standard
errors, fractional score shifts, or stale cache artifacts. The revised system makes
those paths explicit, testable, and fail-closed. If a real signal exists, this gives it a
much better chance of surviving out of sample. If it does not, the system is designed to
say so before money is risked.
